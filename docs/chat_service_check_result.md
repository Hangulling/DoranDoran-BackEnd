### 4. Circuit Breaker 상태 ⚠️

**결과**: 메트릭 데이터를 가져올 수 없습니다

**상세**:
- Resilience4j Circuit Breaker 메트릭이 Actuator에서 노출되지 않음
- 또는 Chat 서비스에 Circuit Breaker가 설정되지 않았을 수 있음

**분석**:
- Chat 서비스는 주로 OpenAI API 호출에 Circuit Breaker를 사용할 것으로 예상
- 하지만 Actuator 메트릭 엔드포인트에서 해당 메트릭이 노출되지 않음
- `ResilienceConfig.java`에 Circuit Breaker가 설정되어 있지만, 메트릭 노출 설정이 필요할 수 있음

**의미**: 
- Circuit Breaker 메트릭을 확인할 수 없어서 상태를 판단할 수 없습니다.
- 실제로는 Circuit Breaker가 작동하고 있을 수 있지만, 메트릭이 노출되지 않아 확인 불가

**권장사항**: 
1. `application-docker.yml`에서 Actuator 메트릭 노출 확인
2. Resilience4j 메트릭이 Prometheus에 노출되도록 설정 확인
3. 또는 로그에서 Circuit Breaker 상태 직접 확인

### 6. 에러 발생 🚨

**결과**: 🚨 심각 (492건, 임계값 10건 대비 매우 높음)

**상세**:
- 최근 5분간 에러 발생 건수: **492건**
- 임계값: 10건 (49배 초과)

**주요 에러 패턴**:

1. **Broken pipe 에러**:
   ```
   java.io.IOException: Broken pipe
   ```
   - 클라이언트가 연결을 끊었을 때 발생하는 에러
   - SSE(Server-Sent Events) 스트리밍 중 클라이언트가 연결을 끊으면 발생

2. **IllegalStateException - block() 에러**:
   ```
   java.lang.IllegalStateException: block()/blockFirst()/blockLast() are blocking, 
   which is not supported in thread reactor-http-epoll-4
   ```
   - Reactor 비동기 환경에서 blocking 호출을 시도할 때 발생
   - WebFlux 비동기 스레드에서 blocking 연산을 수행하려고 할 때 발생

3. **AI 응답 로딩 실패 메시지**:
   ```
   "Failed to load AI response"
   ```
   - AI 응답을 불러오는 중 오류 발생

**분석**:
- 대부분의 에러는 **SSE 스트리밍 관련 에러**로 보입니다
- 클라이언트가 연결을 끊거나, 네트워크 문제로 인한 Broken pipe
- Reactor 비동기 처리 중 blocking 호출로 인한 IllegalStateException
- 실제 서비스 장애보다는 **정상적인 사용 패턴에서 발생하는 에러**일 가능성이 높음

**의미**: 
- 에러 수가 많지만, 대부분이 정상적인 사용 패턴에서 발생하는 에러입니다
- SSE 스트리밍은 클라이언트가 연결을 끊을 수 있으므로 Broken pipe는 예상 가능한 에러
- 하지만 5분간 492건은 상당히 높은 수치이므로 개선이 필요할 수 있습니다

**권장사항**: 
1. **에러 로깅 레벨 조정**: 
   - Broken pipe는 정상적인 사용 패턴에서 발생하므로 WARN 또는 INFO 레벨로 조정
   - IllegalStateException은 코드 레벨에서 수정 필요

2. **코드 개선**: 
   - Reactor 비동기 환경에서 blocking 호출을 제거
   - SSE 연결 종료 시 적절한 에러 핸들링 추가

3. **에러 분류**: 
   - 실제 장애와 정상적인 사용 패턴 에러를 구분하여 로깅
   - 실제 장애만 ERROR 레벨로 로깅

4. **모니터링 강화**: 
   - SSE 연결 상태 모니터링
   - 실제 장애 발생 시 즉시 알림
