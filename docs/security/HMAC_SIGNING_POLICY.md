# HMAC 서명 포맷/키 관리 정책

**작성일**: 2026-01-17  
**대상**: User Service -> Chat Service 내부 API 호출

## 1. 목적

- 내부 서비스 간 호출 위변조 방지
- 게이트웨이 경유 없이도 호출 신뢰성 확보
- 공용 시크릿을 이용한 간단/일관된 인증

---

## 2. 서명 포맷

### 2.1 헤더 규칙

- `X-User-Id`: 호출 주체 식별자 (예: `user-service`)
- `X-Auth-Ts`: 밀리초 타임스탬프 (epoch millis)
- `X-Auth-Sign`: HMAC 서명 값 (hex 문자열)

### 2.2 서명 메시지

```
{userId}|{timestamp}
```

예시:
```
user-service|1705483200123
```

### 2.3 서명 알고리즘

- 알고리즘: HMAC-SHA256
- 인코딩: hex (lowercase)

### 2.4 검증 기준

- `X-Auth-Ts`가 현재 시각 기준 ±5분 이내
- `X-Auth-Sign`이 계산된 값과 일치해야 함
- 서명 실패 시 401 반환

---

## 3. 키 관리 정책

### 3.1 키 위치

- 환경 변수 또는 시크릿 매니저에서 주입
- 설정 키: `gateway.jwt.hmac-secret`

### 3.2 로테이션

- **정기 로테이션**: 분기 1회 권장
- **사고 대응 로테이션**: 유출 의심 시 즉시 교체
- 교체 시 양쪽 서비스에 동시 반영 필요

### 3.3 키 노출 방지

- 로그에 HMAC 시크릿/서명 원문 출력 금지
- CI/CD 환경 변수 마스킹 적용
- 시크릿 값은 저장소에 커밋 금지

---

## 4. 예외/운영 규칙

- 프롬프트 동기화 등 내부 API는 동일한 서명 정책 적용
- 게이트웨이 외부 호출은 별도 JWT 정책 사용
- 서명 검증 실패 시 클라이언트에 원인 상세 노출 금지
