# 데이터베이스 스키마 보고서

**생성일**: 2025-02-02  
**데이터베이스**: dorandoran  
**컨테이너**: dorandoran-shared-db (PostgreSQL 17-alpine)

## 1. 스키마 개요

데이터베이스는 다음과 같은 7개의 스키마로 구성되어 있습니다:

- `auth_schema`: 인증 관련 테이블
- `batch_schema`: 배치 작업 스키마 (현재 테이블 없음)
- `billing`: 과금 및 사용량 추적
- `chat_schema`: 채팅 관련 테이블
- `public`: 기본 스키마
- `store_schema`: 저장소 관련 테이블
- `user_schema`: 사용자 관련 테이블

- `capabilities` (jsonb): AI 모델 기능 및 설정
  ```json
  {
    "model": "gpt-5-mini",                    // AI 모델명
    "modalities": ["text"],                    // 지원 모달리티
    "tools": [],                               // 함수 호출 도구 (추후 확장)

    "topP": 1.0,                              // 토큰 선택 다양성 (0.0-1.0)
    "maxTokens": 800,                          // 최대 응답 토큰 수
    "safety": {                                // 안전 필터 설정
      "profanityFilter": false,                // 욕설 필터
      "piiRedaction": false,                   // 개인정보 마스킹
      "harmfulContent": "allow"                // 유해 콘텐츠 허용
    },
    "responseStyle": {                         // 응답 스타일 제어
      "format": "markdown",                    // 마크다운 포맷
      "bulletPreference": "concise",           // 불릿 포인트 선호도
      "maxLength": 500,                        // 최대 응답 길이
      "includeExamples": true                  // 예시 포함 여부
    },
    "rateLimits": {                            // 속도 제한
      // ... 추가 설정
    }
  }
  ```
- `settings` (jsonb): 챗봇 설정 (concept 등 포함, 구조는 서비스 코드에서 동적으로 관리)

## 4. 주요 특징

1. **스키마 분리**: 기능별로 스키마가 명확히 분리되어 있음
2. **UUID 사용**: 주요 엔티티는 UUID를 기본키로 사용
3. **JSONB 활용**: 유연한 데이터 저장을 위해 JSONB 타입을 적극 활용
4. **소프트 삭제**: 일부 테이블에서 `is_deleted` 플래그를 사용한 소프트 삭제 패턴
5. **인덱스 최적화**: 조회 성능을 위한 다양한 인덱스 구성
6. **외래키 제약조건**: CASCADE 및 SET NULL 옵션을 적절히 사용

## 5. JSONB 필드 요약

다음은 데이터베이스 내 모든 JSONB 필드와 그 구조에 대한 요약입니다:

| 테이블 | 필드명 | 주요 구조 | 설명 |
|--------|--------|----------|------|
| `user_schema.profiles` | `settings` | 동적 구조 | 사용자 프로필 설정 |
| `chat_schema.chatbots` | `personality` | 동적 구조 | 챗봇 성격 설정 |
| `chat_schema.chatbots` | `capabilities` | 고정 구조 | AI 모델 기능 및 설정 (model, temperature, topP, maxTokens, safety, responseStyle, rateLimits 등) |
| `chat_schema.chatbots` | `settings` | 동적 구조 | 챗봇 설정 (concept 등 포함) |
| `chat_schema.chatrooms` | `settings` | 고정 구조 | 채팅방 설정 (concept: FRIEND\|HONEY\|COWORKER\|SENIOR\|BOSS, testModel 등) |
| `chat_schema.chatrooms` | `context_data` | 동적 구조 | 대화 컨텍스트 데이터 |
| `chat_schema.messages` | `metadata` | 고정 구조 | 메시지 메타데이터 (userMessageAnalysis, botResponseAnalysis, usage 등) |
| `chat_schema.intimacy_progress` | `progress_data` | 고정 구조 | 친밀도 학습 진행 데이터 (summaryHistory, keywordIndex, correctionsHistory, lastContextSnapshot) |
| `store_schema.stores` | `ai_response` | 고정 구조 | Multi-Agent AI 응답 (intimacyLevel, description, translation, vocabulary, corrections) |
| `billing.ai_usage_events` | `meta` | 동적 구조 | 추가 메타데이터 |

**JSONB 사용 이유**:
1. **유연한 스키마 변경**: AI 에이전트 응답 구조가 자주 변경됨
2. **부분 업데이트 지원**: PostgreSQL `jsonb_set()` 함수로 특정 필드만 업데이트 가능
3. **인덱싱 지원**: GIN 인덱스로 JSONB 필드 검색 최적화
4. **데이터 구조 특성**: 메시지별로 구조가 다를 수 있음 (user 메시지 vs bot 메시지)
5. **성능 고려**: 메시지 조회 시 metadata는 항상 함께 조회됨

## 6. 참고사항

- 모든 타임스탬프는 `timestamp without time zone` 또는 `timestamp with time zone` 사용
- JSONB 컬럼은 GIN 인덱스를 사용하여 검색 성능 최적화
- 조건부 인덱스(WHERE 절)를 활용하여 삭제되지 않은 레코드에 대한 인덱스 최적화
- 체크 제약조건을 통한 데이터 무결성 보장
