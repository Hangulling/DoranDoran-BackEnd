# 말투 유지를 위한 파인튜닝 필요성 분석

## 현재 구현 상태

### 1. 말투 관리 방식

**VocabularyExplanationAgent:**
- 컨셉/레벨별 말투 규칙을 프롬프트에 명시
- Temperature: 0.5 (자연스러움)
- 규칙 기반 말투 검증 (`isToneAppropriate`)
- 자동 리라이트 기능 (`rewriteExplanation`)

**프롬프트 예시:**
```
FRIEND Level 3 말투 규칙:
- 반말 사용 (예: "~해", "~야", "~지?")
- 친근하고 장난스러운 반말 톤
- 절대 존댓말 사용 금지
```

### 2. 말투 검증 로직

**규칙 기반 검증:**
- FRIEND Level 1/3: 존댓말 패턴 감지 → 리라이트
- COWORKER/BOSS/SENIOR: 반말 패턴 감지 → 리라이트
- 간단한 패턴 매칭 (정규식 기반)

**리라이트 규칙:**
- 간단한 문자열 치환
- 예: "~어요" → "~어", "드셨어요" → "먹었어"

---

## 파인튜닝 필요성 평가

### 현재 방식의 장점

1. **프롬프트로 충분히 제어 가능**
   - 컨셉/레벨별 명확한 규칙
   - Few-shot 예시 포함
   - GPT-4.0 mini의 Few-shot learning 능력 활용

2. **규칙 기반 검증 및 리라이트**
   - 실시간 검증 및 수정
   - 추가 API 호출 없음
   - 비용 효율적

3. **빠른 반복 개선**
   - 프롬프트 수정으로 즉시 개선
   - A/B 테스트 용이

### 현재 방식의 한계

1. **규칙 기반 리라이트의 한계**
   - 간단한 문자열 치환만 가능
   - 복잡한 문맥 변환 어려움
   - 예: "드시다" → "먹다" 같은 동의어 변환

2. **프롬프트 준수율**
   - 모델이 가끔 규칙을 무시할 수 있음
   - Temperature 0.5로 인한 변동성
   - 복잡한 문장에서 말투 일관성 저하 가능

3. **검증 로직의 한계**
   - 패턴 매칭만으로는 모든 경우를 감지하기 어려움
   - 미묘한 뉘앙스 차이 감지 불가

## 파인튜닝이 필요한 경우

### 1. 말투 검증 실패율이 높은 경우

**조건:**
- 로그에서 "말투 검증 실패" 경고가 빈번하게 발생
- 리라이트 후에도 말투가 부자연스러운 경우가 많음
- 사용자 피드백에서 말투 일관성 문제 지적

**측정 방법:**
```java
// 로그 분석
- "VocabularyExplanationAgent: 말투 검증 실패" 빈도
- 리라이트 전후 비교
- 최종 응답의 말투 일관성
```

### 2. 규칙 기반 리라이트로 해결 불가능한 경우

**예시:**
- 복잡한 문맥 변환이 필요한 경우
- 동의어 변환이 필요한 경우
- 문장 구조 자체를 바꿔야 하는 경우

**현재 리라이트의 한계:**
```java
// 현재: 간단한 문자열 치환만
ko.replace("~어요", "~어")

// 필요한 경우: 복잡한 문맥 변환
"드시다" → "먹다" (동의어 변환)
"하시는" → "하는" (문맥 변환)
```

### 3. 프롬프트 강화로도 해결되지 않는 경우

**조건:**
- 프롬프트를 더 상세하게 작성해도 말투 위반 지속
- Few-shot 예시를 늘려도 개선되지 않음
- Temperature를 낮춰도 (0.3 이하) 일관성 문제 지속

## 권장 접근법

### Phase 1: 프롬프트 강화 (즉시 시도)

#### 1.1 Few-shot 예시 강화

**현재:**
```
예시: "'국룰'은 '국민 룰'의 줄임말이야. '당연한 것', '기본'이라는 뜻으로 쓰는 신조어야."
```

**강화:**
```
**[Few-shot 예시 - 반드시 이 패턴을 따르세요]**

컨셉: FRIEND, 레벨: 3
입력: "국룰"
❌ 잘못된 응답: "'국룰'은 '국민 룰'의 줄임말이에요. '당연한 것', '기본'이라는 뜻으로 쓰는 신조어예요."
✅ 올바른 응답: "'국룰'은 '국민 룰'의 줄임말이야. '당연한 것', '기본'이라는 뜻으로 쓰는 신조어야."

입력: "결재"
❌ 잘못된 응답: "'결재'는 직장 상사에게 서류나 계획을 보여드리고 승인받는 것을 말합니다."
✅ 올바른 응답: "'결재'는 직장 상사에게 서류나 계획을 보여주고 승인받는 것을 말해."
```

#### 1.2 말투 규칙 강조

**현재:**
```
**FRIEND Level 3 말투 규칙:**
- 반말 사용 (예: "~해", "~야", "~지?")
- 절대 존댓말 사용 금지
```

**강화:**
```
**⚠️⚠️⚠️ FRIEND Level 3 말투 규칙 (최우선) ⚠️⚠️⚠️**

**반드시 반말만 사용:**
- 종결어미: ~해, ~야, ~지?, ~잖아
- 절대 사용 금지: ~어요, ~해요, ~이에요, ~세요, ~습니다

**Few-shot 예시:**
❌ "'국룰'은 '국민 룰'의 줄임말이에요." (존댓말 - 절대 금지!)
✅ "'국룰'은 '국민 룰'의 줄임말이야." (반말 - 올바름)

**위 예시를 정확히 따라하세요. 존댓말을 사용하면 안 됩니다.**
```

#### 1.3 Temperature 조정

**현재:** Temperature 0.5

**조정 옵션:**
- 말투 일관성이 중요하므로 0.3-0.4로 낮춤
- 단, 너무 낮으면 자연스러움이 떨어질 수 있음
- A/B 테스트로 최적값 찾기

### Phase 2: 리라이트 로직 강화 (필요 시)

#### 2.1 더 정교한 리라이트 규칙

**현재:**
```java
ko.replace("~어요", "~어")
```

**강화:**
```java
// 동의어 변환
ko.replace("드시다", "먹다")
ko.replace("드셨어요", "먹었어")
ko.replace("하시는", "하는")

// 문맥 변환
ko.replace("말씀드리겠습니다", "말해줄게")
ko.replace("보여드리고", "보여주고")
```

#### 2.2 LLM 기반 리라이트 (선택)

**규칙 기반 리라이트가 실패하는 경우:**
```java
// 별도 LLM 호출로 리라이트
private VocabularyExplanationResult llmRewrite(
    VocabularyExplanationResult original,
    String concept,
    int intimacyLevel
) {
    String systemPrompt = """
        위 설명을 {concept} Level {level}에 맞는 말투로 변환하세요.
        반드시 {tone}을 사용하세요.
        """;
    
    // 추가 API 호출 (비용 증가)
    return openAIClient.streamRawCompletion(...);
}
```

## 측정 지표

### 말투 일관성 측정

1. **말투 검증 실패율**
   ```
   실패율 = (말투 검증 실패 횟수 / 전체 응답 수) × 100
   목표: 10% 이하
   ```

2. **리라이트 후 만족도**
   ```
   리라이트 후에도 부자연스러운 비율
   목표: 5% 이하
   ```

3. **사용자 피드백**
   ```
   말투 일관성 관련 피드백 비율
   목표: 5% 이하
   ```

### 로그 분석 방법

```bash
# 말투 검증 실패 빈도 확인
grep "말투 검증 실패" application.log | wc -l

# 리라이트 발생 빈도
grep "리라이트 후" application.log | wc -l

# 최종 응답의 말투 패턴 분석
grep "context.ko:" application.log | grep -E "(어요|해요|이에요|야|해|야)"
```
